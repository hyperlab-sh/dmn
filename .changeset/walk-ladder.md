`dmn replay --as-live` can now be resumed, stopped and watched. The walk keeps a `checkpoint.json` in its `--out` after every prompt — which prompts were seeded or measured, and the measured entries — so running the same command again into the same `--out` skips the checkpointed prompts, walks the rest in timestamp order and writes the report over all entries (the `seeded:` count totals every run into that `--out`); an `--out` holding a run directory but no checkpoint is still refused, and resuming with a different `--measure-from`, `--uses` or `--top` is a usage error before anything is retained. A resumed walk that retains a prompt older than the last checkpointed prompt says so once per prompt in the report `warnings`, because the measurements before it did not see it. `--max-consecutive-failures <n>` (default 5) stops the walk after `n` prompts in a row whose store calls failed — a dead provider costs a few prompts, not hours of judge credit — writing the checkpoint and a report of everything measured so far and exiting 1 with one stderr line naming the count and the last error. A failed recall (store error, timeout) is now a warning that skips only that prompt's measurement; its turns are still retained, so the next prompt recalls them. The walk prints a progress line to stderr every 25 prompts and when a transcript completes: `progress <done>/<total> prompts, <seeded> seeded, <measured> measured, <failed> failed, <mm:ss> elapsed`.
