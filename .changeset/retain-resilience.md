Retain failures no longer abort `dmn replay --as-live` or `dmn backfill`. In an as-live run a retain the store rejects (a store error, a timeout, an HTTP 4xx/5xx from Hindsight) is reported as a warning — `retain failed <transcript>#<index>: <message>` — and the walk continues with the next prompt; later prompts recall everything retained before the failure, and the exit code is unchanged. In `dmn backfill` the transcript's output line counts failed prompts (`failed=N` beside `retained=`), `total retained` counts only successful retains, and the run exits 1 only when nothing was retained at all and at least one retain failed. Neither command retries a failed retain: the retry policy stays Hindsight's own, whose throttling knobs (`HINDSIGHT_API_LLM_MAX_CONCURRENT`, `HINDSIGHT_API_LLM_MAX_RETRIES`, `HINDSIGHT_API_LLM_INITIAL_BACKOFF`, `HINDSIGHT_API_LLM_MAX_BACKOFF`) are now documented in `docs/hindsight.md`, alongside the fact that Anthropic's usage safeguard refuses fact extraction over Claude Code transcripts with the `claude-code` provider (`[reasoning_extraction]`), so ingesting your own Claude history needs another provider.
